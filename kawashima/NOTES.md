# PC側エフェクト（河島・たくみ担当）

3人称カメラ（iPhone）の映像に、センサーの3D情報から計算した魔法エフェクトをThree.jsで重ねて、プロジェクターに映す。

## 動かし方

```
cd sensing/dashboard && npm install && npm start   # センサーの中継サーバー（:8000）
npm run fake                                        # 実機がないときのテストデータ
cd kawashima && node serve.mjs                      # エフェクト画面（:8080）
```

`http://localhost:8080` を開く。別のPCで中継サーバーが動いているときは `?host=IP:8000` を付ける。`?demo` を付けると、両者が相手を狙って自動で撃ち合う。

キー操作は次のとおり。C で設定パネル、G でデバッグ表示（グリッド・当たり判定の範囲）、Space で A が発射、Enter で B が発射、R でリセット。

## 座標の約束

単位はメートルで、y が上。原点は2人の開始位置の中間の床に置く。A は -x 側に立って +x を向き、B は +x 側に立って -x を向く。

- 胸の位置は、開始位置（高さは胸の高さ）に ARCore のキャリブ後の移動量を足して求める
- 棒の向きは、IMU のキャリブ後の姿勢 `q` から求める。キャリブ時に棒を前へ水平に構えておく前提で計算している
- 3人称カメラは、設定パネルのスライダーでグリッドを床の目印に合わせる

## 実機で確認すること

- ARCore の姿勢 `ar.p` は、キャリブ時のカメラの向きが基準になっている（重力の向きには揃っていない）。胸に縦向きで付けたとき、どの軸が上になるかは設定の「AR 上方向」で切り替える。初期値 `-x` は理屈から出しただけで、実機ではまだ確かめていない
- IMU のどの軸が棒の方向になるかは、取り付け方で変わる。設定の「IMU 棒方向」「IMU 上方向」で合わせる
- フェイクデータは AR の x を水平の移動として出すので、初期設定のままだと体が上下に動いて見える。これは設定の問題で、計算の誤りではない
- 振ったかどうかの判定は、ジャイロの大きさがしきい値（初期値 400deg/s）を超えたかで仮に決めている。センサー班の判定が届いたら差し替える
