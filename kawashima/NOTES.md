# PC側エフェクト（河島・たくみ担当）

3人称カメラ（iPhone）の映像に、センサーの3D情報から計算した魔法エフェクトをThree.jsで重ねて、プロジェクターに映す。

## 動かし方

```
cd sensing/dashboard && npm install && npm start   # センサーの中継サーバー（:8000）
npm run fake                                        # 実機がないときのテストデータ
cd kawashima && node serve.mjs                      # エフェクト画面（:8080）
```

`http://localhost:8080` を開く。別のPCで中継サーバーが動いているときは `?host=IP:8000` を付ける。`?demo` を付けると、両者が相手を狙って自動で撃ち合う。

キー操作は次のとおり。C で設定パネル、G でデバッグ表示（グリッド・当たり判定の範囲）、Space で A が発射、Enter で B が発射、R でリセット。

## 決めたこと（10/17 grilling）

| 項目 | 決定 |
|---|---|
| 3人称カメラ | iPhone を連係カメラで Mac に入れる。ブラウザの `getUserMedia` で受け取る |
| 描画 | ブラウザと Three.js で作る。レンダリングやアセットが足りなくなったら Unity に移す |
| 合成の考え方 | Three.js 内に3人称カメラと同じ位置・向き・画角の仮想カメラを置き、センサーの3D座標にエフェクトを描いて実映像に重ねる |
| 共通座標系 | 固定の AprilTag を柱に立てる（後から変更）。胸カメラがタグを見るたびに世界座標へ合わせ直し、見えない間は ARCore で追う（`localize.js`）。3人称カメラもタグから位置を求める |
| プレイヤーのタグ | 胸に貼り、互いの位置を観測するのに使う。ID は固定タグと別にする |
| 棒の先端 | 胸の位置 + 手の固定オフセット + IMU の向き × 既知の棒の長さ |
| 当たり判定 | 3D で取る。飛び道具の球と、相手の胸から下に伸ばした線分との距離で判定する |
| 映像遅延の補正 | 今回はやらない |
| 動作判定（溜め・攻撃・避け） | センサー班（富本・チャオベン）が作る |
| 今日の目標 | 対戦（当たり判定と HP）まで動かす |

## タグ4枚を置くだけでフィールドにする（既定の `layout=map4`）

部屋の大きさもタグの位置も測らない。タグ4枚（ID 0〜3）を好きな場所の床に、だいたい四角形の角になるように置く。向きも間隔も自由でよい。

- 人がいない状態で K（管理画面の「タグでカメラ合わせ」）を押すと、`fieldmap.js` が映像から4枚の位置と向き、カメラの位置と画角を一度に求め、4枚の内側をフィールドにする。大きさの基準は、タグの黒い正方形の一辺（`world.js` の size。ID 0・1 は 200mm、ID 2・3 は 250mm）
- カメラから見て左の2枚の側が A、右の2枚の側が B になる。立ち位置は両端から少し内側に置く
- 3枚しか見えないときは三角形のフィールドになり、「スキャン不十分」と出る。準備完了にするには4枚とも映す
- フィールドの形を変えたいときは、管理画面のプレビューで角を4か所クリックする
- 求め方は、マーカー地図の定番（MarkerMapper、2018年）にならった。タグごとに向きの候補を2つ出し、4枚が同じ床に乗る組み合わせを選んでから、画面上のずれが最小になるよう全体を一括で最適化する。合成データでの誤差は、タグの位置が中央値 1.4cm、画角が 0.3°
- ID 2・3 は `print/corner_tags_A3.pdf` の該当ページを等倍で印刷する

## プレイヤーの位置の取り方（管理画面で切り替え）

- **カメラ映像（既定）**：`posetrack.js` が 3人称カメラの映像から2人の骨格を推定し（MediaPipe Pose Landmarker、Worker で1秒に約15回）、足の位置を床に写してフィールド上の位置にする。棒の根元は手首の位置で、棒の向きは IMU から取る。最初に画面の左にいた人が A。入れ替わったら管理画面の「A・B を入れ替える」を押す
- **胸スマホ**：これまでの ARCore とタグによる位置推定（`localize.js`）
- **固定**：立ち位置から動かない

## 軽さのための工夫

- タグの検出（`tagworker.js`）は別スレッドで動く。準備中の画面のカクつきの主な原因だった
- 管理画面のプレビューは、重いのでなくした
- エフェクトが何も出ていないときは、光のにじみ（ブルーム）の処理を省く
- 描画は 60fps に抑える（`?fps=0` で無制限）。画素数はカメラ映像より細かくしない
- Three.js と js-aruco2 は `serve.mjs` が `vendor/cdn/` に保存して配るので、会場のネットが切れても動く。新しく取得するときは `node serve.mjs --prefetch`
- `?dummy` のダミーの部屋は、設定を本物とは別に保存する

## 2枚の床置き・立てる配置（10/17 午前の配置）

印刷済みのタグ（AprilTag Print Studio 製、黒い正方形 200mm）の ID 0・1 だけを使う。タグを立てておくのが難しかったので、床に置く方式にした。`world.js` の既定（`layout=floor`）がこの配置になっている。立てる方式は `?layout=today`、全部そろったら `?layout=full` で下の6枚配置に切り替える。

- ID 0 は中心から右へ 1.5m・手前（カメラ側）へ 1m の床、ID 1 は左へ 1.5m・手前へ 1m の床に、表を上にして置く。A・B の立ち位置より少しカメラ寄りになる
- **下の文字の行（`tag36h11 | ID: #0 | 200.0mm`）をカメラ側に向けて置く**。カメラから見て紙が正しい向きに読める置き方で、OpenCV から180°回って読まれる分は `world.js` の flip で補正される
- 紙がめくれたり滑ったりしないよう、四隅をテープで留める
- 150mm のほうは同じ ID なので使わない
- タグが必要なのは、3人称カメラのスキャンのときだけ。スキャンのあと iPhone を動かさなければ、タグは片付けてもよい
- iPhone は中心から手前へ 3.5m、高さ 1.7m 以上に横向きで固定し、少し見下ろして床のタグ2枚とフィールド全体を映す。床のタグは斜めから見ることになるので、カメラは高いほど検出しやすい（1.7m で約34°、2.2m で約41°見下ろす）
- ダミーの部屋（`?dummy`）で試したところ、スキャンで求めたカメラの位置は実際の位置と 3cm 以内で合い、誤差は 0.1px だった
- **タグ2枚の間隔と iPhone の画角は、スキャンで測る**。2枚が表を上にして同じ向きに置いてあれば、間隔が 3m でなくても合わせられる。測った間隔はブラウザに保存し、次に開いたときも使う
- 実物で試したときは、iPhone の縦画角が約28°（想定の45°よりかなり狭い）で、ガイドの枠に合わせて置いたタグの間隔は 1.66m になっていた。間隔と画角を測る方式に変えてからは、誤差 0.9px でスキャンが通った
- 映像画面が2つ開いていると、管理画面に2つの状態が交互に出て文字がちらつく。管理画面は表に出ている映像画面だけを表示し、2つ以上あるときは警告を出す。操作は開いている全部の映像画面に届くので、古いほうは閉じる
- 準備中の映像画面には設置ガイドが重なる。タグを置く緑の枠、A・B の立ち位置、フィールドの線を、推奨位置の iPhone から見た位置に描く。実物のタグが緑の枠に重なるように iPhone を動かす
- ガイドの右上の一覧と管理画面に、各タグが見えているか、左右が合っているかが約1秒ごとに出る。全部 OK になったら、人がいない状態で K（管理画面の「タグでカメラ合わせ」）を押す
- 合わせたあとの枠は、計算したカメラから描く。枠と実物が重なっていれば合わせは正しい。古い合わせ結果が残っているときは、管理画面の「ガイドを推奨位置から表示」で推奨位置からの表示に戻す

## 管理画面と映像画面

画面は2つに分かれている。どちらも同じ Mac の同じ Chrome で開く（BroadcastChannel でつながるため）。

- **管理画面** `http://localhost:8080/admin.html`：操作する人の画面。試合の進行、カメラ合わせ、表示の切り替え、テスト発射など、下のキー操作はすべてボタンでもできる。映像画面の縮小プレビューと、スマホ・位置推定・カメラの状態も出る
- **映像画面** `http://localhost:8080/`：プレイヤーと観客が見る画面。管理画面の「映像画面を開く」で開き、プロジェクター側のディスプレイへ移して全画面（⌃⌘F）にする。状態の文字はデバッグ表示（G）のときだけ出る

試合は「準備中 → デモ → 試合開始 → 試合終了」と進む。

- **準備中**（1）：エフェクトは出さない。ページを開いた直後はこの状態になる。タグを置いて K でスキャンし、固定タグが全部見えて誤差が 4px 未満なら「準備完了」になる
- **デモ開始**（2）：両者が自動で撃ち合う。HP は減らない。スキャンが済むまでは押せない
- スキャンをやり直す時間がないときは、管理画面の「スキャンせずに開始可能にする」で前回の合わせ結果のまま始められる
- **試合開始**（3）：スキャンが済むまでは押せない。3秒数えてから始まる。HP が0になるか、試合時間（初期値90秒）が切れたら終わる。時間切れは HP が多い方の勝ちで、同じなら引き分け
- **一時停止**（4）：試合中とデモ中に止める。もう一度押すと再開する
- **やり直し**（R）：今の段階を最初からやり直す。試合終了のあとに押すと、次の試合のカウントダウンが始まる

映像画面が裏のタブに隠れていると、Chrome が描画を止めるので試合の時計も進まない。映像画面は必ず別のウィンドウで表に出しておく。

## フィールドの設置（全6枚の配置）

印刷物は `kawashima/print/` にある。`corner_tags_A3.pdf`（固定タグ ID 0〜5、黒い正方形 25cm）と `chest_tags_A4.pdf`（胸タグ ID 10・11、18cm）の2つ。作り直すときは `python3 kawashima/print/make_tags.py` を実行する。

1. **等倍で印刷する。** 「用紙に合わせる」は切る。印刷したら黒い正方形を定規で測り、25cm・18cm からずれていたら `world.js` の `TAGS` の size を実測値に直す
2. **フィールドを床にテープで描く。** 4m × 4m の正方形で、中心が原点。3人称カメラから見て、左が A 側（-x）、右が B 側（+x）、奥が -z になる
3. **固定タグを6枚立てる。** タグの中心を床から 1.3m の高さにして、面をフィールドの中心へ向ける。柱がなければ、椅子や箱に貼ってもよい。`make_tags.py` の PDF は、見出しの文字が上に来る向きで貼る。公式画像と同じ向きで印刷したタグを使うときは、`world.js` の該当タグに `flip: true` を付ける。ID 2・3 は手前の3人称カメラに背を向けるので、カメラ合わせには 0・1・4・5 を使う

| ID | 位置 (x, z) | 場所 |
|---|---|---|
| 0 | (-2, -2) | 左奥の角 |
| 1 | (+2, -2) | 右奥の角 |
| 2 | (+2, +2) | 右手前の角 |
| 3 | (-2, +2) | 左手前の角 |
| 4 | (+2, 0) | 右の辺の中央（B の真後ろ） |
| 5 | (-2, 0) | 左の辺の中央（A の真後ろ） |

4. **開始位置に印を付ける。** A は (-1.2, 0) で +x 向き、B は (+1.2, 0) で -x 向きに立つ。間隔は 2.4m
5. **3人称カメラ（iPhone）を置く。** 手前側（+z）の中心から 4m ほど離し、高さ 1.6m 前後の三脚に載せる。フィールド全体と、固定タグが2枚以上映る向きにする
6. **胸に付ける。** スマホは胸の中央に縦向きで付け、胸タグはその近くに正面向きで貼る。タグがスマホのカメラを隠さないようにする
7. **スマホ側の設定。** タグサイズの欄は、印刷したサイズに関係なく 0.1 のままにする。実寸への換算は PC 側で ID ごとにやる。開始位置で棒を前に水平に構え、Calibrate を押す

部屋が 4m 四方に収まらないときは、実際に測った寸法を `world.js` の `ARENA` と `TAGS` の座標に書き込む。

## 座標の約束

単位はメートルで、y が上。原点は2人の開始位置の中間の床に置く。A は -x 側に立って +x を向き、B は +x 側に立って -x を向く。

- 胸の位置は、開始位置（高さは胸の高さ）に ARCore のキャリブ後の移動量を足して求める
- 棒の向きは、IMU のキャリブ後の姿勢 `q` から求める。キャリブ時に棒を前へ水平に構えておく前提で計算している
- 3人称カメラは、設定パネルのスライダーでグリッドを床の目印に合わせる

## 実機で確認すること

- ARCore の姿勢 `ar.p` は、キャリブ時のカメラの向きが基準になっている（重力の向きには揃っていない）。胸に縦向きで付けたとき、どの軸が上になるかは設定の「AR 上方向」で切り替える。初期値 `-x` は理屈から出しただけで、実機ではまだ確かめていない
- IMU のどの軸が棒の方向になるかは、取り付け方で変わる。設定の「IMU 棒方向」「IMU 上方向」で合わせる
- フェイクデータは AR の x を水平の移動として出すので、初期設定のままだと体が上下に動いて見える。これは設定の問題で、計算の誤りではない
- 振ったかどうかの判定は、ジャイロの大きさがしきい値（初期値 400deg/s）を超えたかで仮に決めている。センサー班の判定が届いたら差し替える

## 未決事項

- センサー班とのメッセージ形式（Q9）。溜め・発射・避けをどういう JSON で受け取るかを、センサー班と決める
- ゲーム状態の持ち主（Q10）。共有したいが、当面はこのページの中で持つ。描画する画面を増やすときや、振動・光をスマホへ返すときは `server.mjs` 側へ移す
- 当たったときの振動と光。いまの `server.mjs` には、PC からスマホへ命令を返す経路がない。センサー班に相談する
- Three.js は CDN（jsdelivr）から読み込んでいる。会場のネットが不安定なら、手元にファイルを置く
